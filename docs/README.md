# Startup Igniter — Documentation

This is the canonical documentation for the AI reasoning pipeline: what each
phase does, what each agent does, why the architecture looks the way it
does, and how to operate the self-hosted model infrastructure. It supersedes
the phase/agent descriptions in the root-level spec files
(`ai-startup-navigator-spec.md`, `ai-startup-navigator-spec-v2.md`,
`FRONTEND_SPECIFICATION.md`, `implementation_plan.md`) wherever they
disagree — those documents describe earlier design intent (including an
Anthropic-Claude-based model choice the code never actually used; see
[ADR 0001](architecture/0001-llm-gateway.md)) and are kept for historical
context, not as a live source of truth.

## Canonical taxonomy

**12 crews, 66 agents** (plus the skeptic crew), per `frontend/src/data/crews.ts` — the newest
taxonomy and the one the shipped UI actually shows. Four *other*,
inconsistent descriptions exist elsewhere in this repo; see
[ADR 0004](architecture/0004-taxonomy-conflict.md) for why this one was
picked and what the others actually mean (they're not all naming variants of
the same thing — the DB-backed `WorkflowEngine`'s 6 phases are a genuinely
separate system).

### Implementation status

All **12 crews are implemented**, plus a 13th **skeptic** crew
([ADR 0006](architecture/0006-evidence-ledger-and-skeptic.md)). Crews 1-3
(20 of 66 agents, plus 1 unlisted 7th agent, see
[docs/agents/67-existing-solution-analyzer.md](agents/67-existing-solution-analyzer.md))
make one schema-validated LLM call per agent. Crews 4-12 run as **one
structured call per crew** through `ai/crews/spec_runner.py`, using the phase
and agent docs in this folder as the system prompt, so those docs are code
inputs: keep their header format. Claims in the output are verified against a
shared source pool by the evidence ledger. Badges on the docs under
`docs/agents/` and `docs/phases/`:

- 🟢 **IMPLEMENTED** - one real, schema-validated LLM call per agent.
- 🟢 **IMPLEMENTED (crew-level)** - the agent is a role inside a crew's single call.

The pipeline entry is `ai/pipeline.py::run_pipeline`. The product around it
(accounts, billing, chat, integrations) is in [product.md](product.md).

## Agents

66 individual agent docs (plus the 1 unlisted implemented agent) live under
[`docs/agents/`](agents/), generated by [`docs/generate_docs.py`](generate_docs.py)
from `frontend/src/data/crews.ts` cross-referenced against the actual Python
implementation. Regenerate after any change to that file or to a Pydantic
schema in `ai/schemas/`:

```bash
python docs/generate_docs.py
```

## Schemas

Every real Pydantic output schema (the per-agent schemas for crews 1-3,
plus the crew-level result schemas for crews 4-12 and the skeptic) is exported as
JSON Schema under [`docs/schemas/`](schemas/), also via the generator above —
these are never hand-written, so they can't drift from the actual code.

## Contributing to these docs

- **Phase docs** (`docs/phases/`) and **ADRs** (`docs/architecture/`) are
  hand-written. Update them when the described behavior actually changes —
  they're process documentation, not a changelog.
- **Agent docs** (`docs/agents/`) and **schema JSON** (`docs/schemas/`) are
  generated. Don't hand-edit them; update `docs/generate_docs.py`'s data (if
  the taxonomy changed) or the Pydantic schema (if the output shape changed)
  and re-run it.
